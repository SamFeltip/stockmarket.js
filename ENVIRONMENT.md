# Web and Convex environment

Configuration belongs to this repository and its selected Convex deployment, not the parent workspace. Run commands here, or use `npm run <script> --prefix stockmarket-convex` from the parent. npm runs scripts in this repository, so Vite and the Convex CLI read this directory's files.

## Local web configuration

After `npm ci`, run `npx convex dev --once`. On a fresh checkout, sign in and select the intended development project. Convex writes ignored `.env.local`. The tracked `.env.example` documents its keys; it contains no credentials. Preserve an existing `.env.local` rather than overwriting it.

| Variable | Source | Purpose |
| --- | --- | --- |
| `CONVEX_DEPLOYMENT` | CLI-managed `.env.local` | Selects the development deployment for Convex commands. |
| `VITE_CONVEX_URL` | CLI-managed `.env.local` | Backend URL embedded in the browser bundle. |
| `CONVEX_DEPLOY_KEY` | Hosting/CI secret or invoking process, when needed | Authenticates automated Convex deployments. Do not add it to frontend configuration or Git. |

`npm run dev` starts the backend watcher and frontend. Restart Vite after editing env files; rebuild deployed bundles after changing URLs. Vite loads `.env`, `.env.local`, `.env.[mode]` and `.env.[mode].local` from this repository. Mode-specific files override generic ones, and variables already supplied by the invoking process take priority. `.env.example` is documentation and is not loaded automatically. There is no need to shell-source Vite env files or copy them to the parent.

All `VITE_*` values are public client configuration. Never give passwords, signing keys or deployment credentials that prefix. Vite's `BASE_URL` is generated by its configuration, not a user secret.

## Convex server configuration

The server reads the selected deployment's environment, not the browser's `.env.local`. Configure values through the Convex dashboard or `npx convex env set NAME` (which prompts for the value). Add `--prod` only when intentionally configuring production. Development and production values are separate.

| Variable | Source | Purpose |
| --- | --- | --- |
| `JWT_PRIVATE_KEY` | Deployment environment | Private password-auth signing key. |
| `JWKS` | Deployment environment | Matching public verification keys. |
| `CONVEX_SITE_URL` | Supplied by Convex | Auth issuer used by `convex/auth.config.ts`. Do not replace it with the frontend URL. |
| `NPC_DISABLE_NEW_GAMES` | Optional deployment environment | Exact value `true` prevents enabling NPCs for new games; unset leaves normal behavior enabled. |

For an entirely new, unconfigured development deployment, run `node scripts/init-auth.mjs` once. It sends the generated key pair directly to that deployment. Do not run it on an already configured deployment unless deliberately rotating keys. Existing production keys are already configured. The helper accepts `--prod` for initial setup of a new production deployment only.

Auth-library redirect flows, if enabled later (for example OAuth or email links), also use deployment-side `SITE_URL` for the allowed frontend origin. The current username/password app does not require adding it to the frontend env file.

## Production builds

Use the workspace [deployment guide](https://github.com/SamFeltip/stockmarket-game-engine/blob/main/DEPLOYMENT.md). `npm run deploy:backend` invokes Convex's production deploy and passes its URL to the frontend build as `VITE_CONVEX_URL`; `deploy:frontend` uploads that bundle. Do not upload a development build pointing to `.env.local`'s development backend. Existing Convex/Cloudflare login credentials are managed by those CLIs outside the repository.

Environment files are ignored, apart from `.env.example`. Keep local values in this repository and server secrets in Convex or the deployment platform. The shared engine and headless environment need no environment variables.
